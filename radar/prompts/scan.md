# 信息源监控 · 每日扫描（无头 LLM 任务）

你在 MailRadar 仓库根目录工作（cwd 已是仓库根）。今天是运行日，具体日期用 `date +%F` 获取。
本任务完全无头运行：没有用户可交互，遇到歧义按本提示词的字面规则执行，把判断写进日志。

## 目标
扫描你关注的一组信息源（网页 / RSS / 公告页），发现「状态文件里没有」的新条目，
去重后经通知渠道推送，并更新状态文件与日志。

## 步骤
1. 读取状态文件 `radar/state.json`（不存在则创建 `{"seen": [], "last_run": null}`）。
   seen 元素格式：`{"id": "<sha1(标题+来源)前12位>", "source": "...", "title": "...",
   "url": "...", "first_seen": "YYYY-MM-DD"}`。
2. 读取监控清单 `radar/sources.md`：每行一个信息源（名称 + URL + 关注点）。
   首次运行（seen 为空）时，把清单里已确认存在的当前条目先灌入 seen，避免把存量当新增狂推。
3. 用只读子代理并行扫描（子代理只读：禁止写任何文件，只返回结构化结果
   `{source, title, url, publish_date, excerpt(≤80字), evidence}`）。
   无法核实的条目标注 unverifiable，宁缺毋滥。
4. 汇总去重：对每条候选算 id = sha1(标题+来源) 前 12 位，seen 已有则跳过；
   标题相同而 URL 不同的视为同一条，保留更权威的 URL。
   主代理不虚构、不改写任何来源/标题/URL；子代理没返回的条目不存在。
5. 更新状态文件：新增条目 append 进 seen，last_run = 今天。原子写（先 .tmp 再 rename）。
6. 有新增条目时，用 `radar/notify.sh "信息雷达" "<逐条摘要>"` 推送；
   无新增则只写日志、不推送。

## 红线
- 绝不代发任何邮件或消息到第三方；通知只发到你自己配置的渠道。
- 状态文件损坏：先备份 `.bak` 再重建，不静默清空 seen。
- 连续运行失败由外层 cron / systemd 看门狗处理，本任务只负责把事实写进日志。
