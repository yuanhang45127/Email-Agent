# 外联评估（先评估、后行动的人机协同契约）

本技能把「向联系人发起外联」拆成两个阶段，中间必须有人确认：

- **阶段一 · 评估（只读）**：核对纪律硬门槛 + 背景，产出结论 JSON 与 Markdown 报告；
- **阶段二 · 推草稿（人确认后）**：生成草稿、推入 IMAP 草稿箱、回写状态列。

**无头模式无法交互：禁用 AskUserQuestion，一切确认已由调用方（面板/脚本）完成。**
除指定的结果文件外，不写任何其他文件；评估阶段不得修改任何联系人表 / git 仓库。

## 阶段一 · 评估（只读 + 可选联网）

按调用方给出的联系人行执行：

1. **纪律硬门槛**（任一命中 → `recommendation="blocked"`，reason 写清原样，不做后续调研）：
   - 已发送=是，或状态含 已婉拒/已排除/退信/冻结/勿发；
   - 邮箱=待核实（可先联网核实并注明来源；核实不到 → blocked）；
   - 业务规则：如同一分组内已有活跃外联线且本行无明确并行授权。
2. **背景核对**（过门槛后）：公开主页/资料确认身份与近况，结合调用方给出的自身背景，
   给出契合点与卖点排序。
3. **结果 JSON 写入调用方指定路径**：`summary` / `fit` / `discipline`（各项纪律检查）/
   `recommendation`（yes|warn|no|blocked）/ `reason`。
4. **沉淀报告**：同次评估写一份 Markdown 到 `reports/评估_<名称>_<YYYYMMDD>.md`（blocked 也写）。
5. stdout 只回一行确认。

## 阶段二 · 推草稿（人确认后）

调用方已看过评估并点击确认。按给定步骤执行（写/复用草稿 → 推草稿箱 → 只读核对无重复 →
回写状态列并单独 git commit）。红线：

- **绝不代发邮件**（发送由人手动完成）；
- 推箱 append-only，按 (主题, 收件人) 去重，可安全重复运行；
- 草稿箱里已有同主题同收件人的草稿则跳过。
